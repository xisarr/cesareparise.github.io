Model and timing notes

In movie mode the slider changes both playback and model inputs: negative delays the sound, positive delays the picture. In live mode it changes the model inputs only; the microphone is not played through the speakers. Model states normally persist across movie loops; optional cut suppression re-establishes only visual states at cuts. Changing model/input settings restarts processing; display gains do not.

Scientific and technical notes

The numerical engine is written in C and compiled to WebAssembly, with SIMD acceleration where supported. It follows the implementation in MCDq.m, including biphasic temporal filters, unsigned transient energy, and delayed multiplicative interactions. It produces two numerical outputs: a correlation response that reflects the strength of audiovisual temporal correspondence, and a signed lag response that reflects the direction of the temporal offset between the signals. The default human temporal constants are 45 ms (visual), 36.7 ms (auditory), and 180 ms for both second-stage filters. The rat preset uses 10 ms (visual), 10 ms (auditory), and 138 ms for both second-stage filters. Each preset restores global scaling to 1× and clears filter states and traces without changing the imposed audiovisual delay or display settings.

For negative imposed delays the auditory input is delayed; for positive delays the visual input is delayed. Brief signal histories implement this experimental manipulation. Video delays use available frame timestamps, so a 10 ms slider step does not imply 10 ms video resolution. Live camera/microphone acquisition offsets are not calibrated. Recorded-file timing uses the movie timestamps and a decoded mono envelope. Movie playback uses the same relative offset: a causal audio delay for negative settings and buffered video frames for positive settings. Device output latency is not calibrated.

When editing-cut suppression is enabled, automatically detected scene cuts and movie loop boundaries re-establish the visual baseline while retaining auditory filter states. Disabling it preserves all states. Manual seeking starts a new analysis segment and clears both sensory histories; ordinary detected cuts reset only the visual pathway. Automatic cut detection is heuristic and uses a fixed balanced sensitivity. The bipolar lag map represents signed detector output, not an estimated delay in milliseconds. Logarithmic display is 20 log10(1 + magnitude/reference), a soft-log visual convention, not sound pressure level. Output colour and gain affect display only.

Linear filter cascades are advanced analytically for the actual sample interval; Gauss–Legendre quadrature integrates the nonlinear transient drive into the second-stage filters. Captured frames are processed in order. If processing falls substantially behind or input is interrupted, both pathways are explicitly re-primed at the current sample rather than pretending that missing frames were observed. Such resynchronisations are counted in the timing diagnostics and leave gaps in the traces. Detected editing cuts still re-establish only the visual baseline.

Very short effective constants cannot recover temporal detail absent from the camera frames. Increase spatial downsampling if the processing counters show skipped updates. This interactive demonstration is NOT a calibrated psychophysical experiment.

Privacy and usage statistics

Your webcam images, microphone audio and movie files are processed on your device. They are not uploaded.

On the published site, Cloudflare Web Analytics records page traffic. When enabled, a separate counter records whether this page successfully ran the model, which input modes were used, and whether it completed 30 seconds of active, visible processing. It uses a temporary random page token, not a name or a persistent visitor identifier. No recordings, filenames, model values or device labels are sent.

Local previews are excluded. The usage counter does not use cookies or browser storage and does not write IP addresses or browser identifiers to its database. Cloudflare still handles ordinary network metadata to deliver these services.
